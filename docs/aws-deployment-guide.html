1. Kalin thibba Setup eka vs Den thiyena Setup eka

Local development ekedi frontend eka saha backend eka oyage laptop/PC eke witharak run wenawa. Ekath ekk process ekak — internet ekata expose wenne naha. AWS ekata giyama, ee components okkoma cloud eke, thani thani managed services vidiyata host wenawa.

Before — Localhost

PartKalin thibba vidiya
Frontendnpm run dev → localhost:3002
Backendnpm run start:dev → localhost:3000
DatabaseLocal PostgreSQL (localhost:5432)
EmailSMTP (Gmail/Mailtrap) or console log
AccessOyage machine ekata witharak — public eken access wenne naha
ScalingEkak process — traffic wadi unoth crash wenna puluwan

After — AWS Production

PartDen thiyena vidiya
FrontendNext.js → CloudFront CDN (worldwide fast delivery)
BackendNestJS → AWS Lambda (serverless, auto-scale)
DatabaseAWS RDS PostgreSQL (managed, private VPC eke)

ScalingAutomatic — traffic wadi unath Lambda auto scale wenawa
Key Idea 💡 Code eke business logic eka (controllers, services, components) wenas wenne naha. Wenas wenne — eeka run karana infrastructure eka witharai. Local eke "process" ekak, AWS eke "managed cloud service" ekak.

2. Ai me widiyata change karanna one? (Why AWS / SST)

  • Public access — Client ekata / users ta app eka use karanna internet eken puluwan wenna one.
  • Reliability — Oyage laptop off unoth app eka down wenna baha. AWS 24/7 uptime.
  • Scaling — Users 10ka wela 10,000ka una vitharath Lambda + CloudFront automatic scale wenawa, server manage karanna one na.
  • Security — Database eka private VPC ekaka, internet ekata direct expose wenne na.
  • Cost efficiency — Serverless nisa, traffic naththam almost $0 — pay only for what you use.

SST (Serverless Stack) kiyanne — AWS resources (Lambda, RDS, CloudFront, VPC...) eka TypeScript code walin define karala, single command ekaka deploy karanna puluwan wana Infrastructure-as-Code (IaC) framework ekak.

Why VPC Endpoint? Lambda eka VPC ekaka thiyenne (RDS ekata private connect karanna). Ehema VPC ekak eke thiyena Lambda ekakta normal internet access nathi (NAT Gateway naththam — eka cost wadi karanawa). Ithin SES ekata call karanna VPC Interface Endpoint ekak add kala — eken NAT gateway ekak nethuwa SES ekata private widiyata connect karanna puluwan.

5. Code eke une changes

Backend — Express server ekak nathiwa Lambda handler ekak

Local eke NestJS eka app.listen(3000) widiyata continuous server ekak vidiyata run wenawa. AWS Lambda ekedi eka "on-demand" — request eka awoth witharak run wela, awasan unama nawathinawa. Ithin backend/src/lambda.ts kiyala adapter ekak danna one: 

// backend/src/lambda.ts
import serverlessExpress from '@vendia/serverless-express';
import express from 'express';
import { createNestApp } from './app.factory';

let cachedHandler;

async function bootstrap() {
  const expressApp = express();
  await createNestApp(expressApp);
  return serverlessExpress({ app: expressApp });
}

export const handler = async (event, context) => {
  context.callbackWaitsForEmptyEventLoop = false;
  cachedHandler ??= await bootstrap();
  return cachedHandler(event, context);
};

@vendia/serverless-express package eka Express app ekak Lambda event/response format ekata convert karanawa. cachedHandler use karanne — Lambda "warm" wela thiyenakota, ape NestJS app eka repeat wela bootstrap karanna one na (faster response).

Environment Variables — .env file eken Secrets ekata

Local eke .env file ekaka database password, JWT secret danawa. Production eke ehema karanna baha (git ekata commit unoth security risk). Ehenma SST Secrets use kalා: 

// infra/secrets.ts
export const jwtSecret = new sst.Secret("JwtSecret");
export const sesSenderEmail = new sst.Secret("SesSenderEmail");

❯ npx sst secret set JwtSecret "super-secret-value" --stage production

Database Connection — localhost eken RDS host ekata

Local .envProduction Lambda environment
POSTGRES_HOST=localhostPOSTGRES_HOST=<rds-endpoint>.rds.amazonaws.com
POSTGRES_SSL=falsePOSTGRES_SSL=true

SST eke link: [postgres] danata, RDS host/port/user/password auto-inject wenawa — manual configure karanna one na.

Frontend — API URL eka dynamic karanawa

// infra/web.ts
export const web = new sst.aws.Nextjs("Web", {
  path: "frontend",
  environment: {
    NEXT_PUBLIC_API_URL: $interpolate`${api.url}/api`,
  },
});

Local eke NEXT_PUBLIC_API_URL=http://localhost:3000/api hardcode kala. Production eke, API Gateway eka deploy unama generate wena real URL eka automatic widiyata frontend ekata pass wenawa — manual update karanna one na.

6. Anith Localhost Project ekak Deploy karanna Steps

Oyage anith project ekakwath methis (backend + frontend + DB) thiyenam, me steps follow karanna puluwan:

  1. 1

    AWS account + CLI setup

    AWS account ekak hadanna. aws configure run karala credentials danna (Access Key / Secret Key — IAM user ekakata create karanna).

  2. 2

    SST install karanna

    npm install --save-dev sst @pulumi/aws @pulumi/pulumi
npx sst init
  3. 3

    sst.config.ts + infra/ folder hadanna

    Region eka, app name eka, stages (dev/production) define karanna. Ape project ekedi infra/database.ts, infra/api.ts, infra/web.ts, infra/secrets.ts widiyata separate files walin organize kala.

  4. 4

    Backend eka Lambda-compatible karanna

    Framework eka (NestJS/Express) direct app.listen() karanawanam, eka Lambda handler ekakata wrap karanna one (serverless-express wage adapter ekak use karanna).

  5. 5

    Database eka RDS ekata move karanna

    sst.aws.Postgres (or MySQL) component ekak use karanna. vpc ekaka danna — public ekata expose karanna epa.

  6. 6

    Secrets migrate karanna

    .env file eke thibba sensitive values okkoma sst.Secret ekata move karanna: npx sst secret set NAME value --stage production

  7. 7

    Frontend eka connect karanna

    sst.aws.Nextjs (or static site) component ekak use karala, API URL eka $interpolate ekak use karala dynamic widiyata pass karanna.

  8. 8

    Deploy karanna

    npx sst deploy --stage production
  9. 9

    CI/CD add karanna (optional but recommended)

    GitHub Actions eken main branch ekata push unama automatic deploy wenna workflow ekak hadanna (OIDC role use karala AWS credentials expose karanna one na).

8. Cost eka gana danna one dewal

⚠️ AWS eka "pay as you go" Resources run wenakota witharak charge wenawa, eth RDS database eka 24/7 run wela thiyenawa unoth — traffic ekak nathath, cost eka enawa.
ResourceApprox monthly cost
RDS (db.t4g.micro)~$14
VPC Interface Endpoint (SES)~$7–15
Lambda / API Gateway / CloudFrontTraffic base — low traffic ekata almost $0–2

Dev/test karana stage ekak (e.g. saliya) use karala inne nathnam: npx sst remove --stage saliya kiyala remove karanna — RDS + VPC delete wela cost eka stop wenawa. Production stage eka witharak permanent run karanna.

9. Common Mistakes / Gotchas (api dan gunu)

❌ npm exec sst deploy --stage production npm eka --stage flag eka swallow karanawa. ./node_modules/.bin/sst deploy --stage production widiyata direct binary eka call karanna.
❌ Ekama SES email address, wenwena stages walin create karanawa SES identities account-wide widiyatai — dev stage eka verify kala email eka, production stage eken "already exists" error ekak denawa. Email.get() use karanna, or manual widiyata IAM permission ekak witharak dila SDK eken direct call karanna.
⚠️ SES Sandbox mode AWS account ekak default eke SES "sandbox" mode ekaka thiyenawa — sender saha recipient dෙkama verify karanna one. Production access request karanna one (domain verify karanna one).
⚠️ VPC eke Lambda ekakata internet access na NAT Gateway naththam, VPC eke Lambda ekakata external services (SES, third-party APIs) ekata call karanna baha. VPC Interface Endpoint ekak add karala private route ekak hadanna one (NAT Gateway eken wada cheap).
✅ Seed / migration Lambda ekak thiyanna Deploy unama admin user auto create wenne na — separate Seed function ekak hadala, CI/CD eke deploy step eka passe invoke karanna one.
